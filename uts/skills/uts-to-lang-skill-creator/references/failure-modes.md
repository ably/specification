# Common failure modes and remedies

Part of the `uts-to-lang-skill-creator` skill: read [SKILL.md](../SKILL.md) first (ground rules, stop points, path convention). Links that climb out of the skill directory are spec-repo paths: resolve them against the spec clone, not against this file's installed location.

All from the guide and the UTS docs; follow the link for the detail.

| Symptom | Likely cause | Remedy | Source |
|---|---|---|---|
| Tests compile but the runner collects none (or fewer than the tags) | Names don't match the runner's collection rules | Fix the resolver's naming (D-04); compare the distinct collected test functions (a parameterised test counted once) with the tag count | guide [10](../../../docs/writing-uts-spec-translator-skills.md#10-verification-and-ci), [5.1](../../../docs/writing-uts-spec-translator-skills.md#51-traceability) |
| Integration waits time out instantly with a misleading timeout message | The runner virtualises time; the timeout measures virtual time | Wrap every real-network wait in a wall-clock helper | `writing-derived-tests.md` "Integration timeouts are wall-clock"; guide [5.6](../../../docs/writing-uts-spec-translator-skills.md#56-time-and-waiting) |
| A poll under fake timers never expires | The poll deadline reads the faked clock | Restructure to avoid stubbing the wall clock, or read a monotonic clock | `writing-derived-tests.md` "No real timers in unit tests"; guide [5.6](../../../docs/writing-uts-spec-translator-skills.md#56-time-and-waiting) |
| Retries fire on wall-clock time despite `ADVANCE_TIME` | A timed blocking wait or a runtime timer isn't on the fake clock | Extend the clock hook to every time source (P-11) | guide [2.1](../../../docs/writing-uts-spec-translator-skills.md#21-sdk-test-hooks-must) |
| A wait misses a transient state | Sampling wait, or check-before-subscribe race | Event-latched `AWAIT_STATE`; record-and-verify with `CONTAINS_IN_ORDER` | guide [5.7](../../../docs/writing-uts-spec-translator-skills.md#57-waits-must-catch-events) |
| `CONTAINS_IN_ORDER` fails although the states occurred | Rendered as a contiguous prefix or an exact filtered list | Subsequence helper | guide [6.7](../../../docs/writing-uts-spec-translator-skills.md#67-notes-on-the-catalogue) |
| A state wait runs out the timeout after the connection failed | No fail-fast on FAILED | Fail immediately on FAILED, except when the test just requested a transition out of it | guide [5.7](../../../docs/writing-uts-spec-translator-skills.md#57-waits-must-catch-events) |
| Assertions after a poll see fewer items | The test re-reads after polling an eventually-consistent store | Use the value the poll returned | guide [5.7](../../../docs/writing-uts-spec-translator-skills.md#57-waits-must-catch-events) |
| `poll_until_success` times out with no useful error | Emulated with a reader that swallows errors | A separate helper that rethrows the last error | guide [5.7](../../../docs/writing-uts-spec-translator-skills.md#57-waits-must-catch-events); `uts/README.md` |
| Negative assertions pass or fail at random | One zero-delay yield doesn't drain chained callbacks | Drain until the internal queue is empty; or the quiescence control-listener | guide [2.6](../../../docs/writing-uts-spec-translator-skills.md#26-understand-the-sdks-concurrency-model-must); `standard_test_pool.md` "Negative-assertion quiescence" |
| Tests pass alone, fail together | Process-global hooks with a parallel runner; leaked clients or timers | Serialise or make hooks per-client (D-14); close clients and restore mocks in teardown | guide [2.6](../../../docs/writing-uts-spec-translator-skills.md#26-understand-the-sdks-concurrency-model-must), [5.4](../../../docs/writing-uts-spec-translator-skills.md#54-setup-and-teardown) |
| State machine misbehaves only under the mock | Mock `close()` calls `onClose` synchronously, or CONNECTED arrives before the connection completes (often an existing double reused unchanged) | Fix or wrap the mock per `mock_websocket.md` | guide [2.2](../../../docs/writing-uts-spec-translator-skills.md#22-a-shared-test-library-implementing-the-helper-specs-must) |
| An objects test's operation is silently ignored | Hand-written serial literal sorts before the pool serial | Use the serial helpers | `standard_test_pool.md`; guide 2.2 |
| Proxy session creation fails with HTTP 400 | Numeric `match.action` | Stringify it in the rule builder | guide [2.4](../../../docs/writing-uts-spec-translator-skills.md#24-the-proxy-must-for-the-proxy-tier); `proxy.md` |
| A proxy rule never fires | Action name beyond the proxy's name table (`OBJECT`, `OBJECT_SYNC`, `ANNOTATION`) | Use numeric strings (`"19"`, `"20"`, `"21"`) | `proxy.md` "Match Conditions"; guide [2.4](../../../docs/writing-uts-spec-translator-skills.md#24-the-proxy-must-for-the-proxy-tier) |
| Proxied client fails to authenticate | Basic auth over the plain proxy hop (RSA1) | Token auth through the proxy, with a comment | guide [2.4](../../../docs/writing-uts-spec-translator-skills.md#24-the-proxy-must-for-the-proxy-tier) |
| Duplicate sandbox apps; flaky provisioning | `POST /apps` retried | Retry only idempotent requests; check the status before parsing | guide [2.3](../../../docs/writing-uts-spec-translator-skills.md#23-sandbox-provisioning-and-fixtures-must-for-integration-tiers) |
| Resource leaks after objects integration tests | REST provisioning client not closed | Close it | `standard_test_pool.md` "REST Fixture Provisioning"; guide [2.2](../../../docs/writing-uts-spec-translator-skills.md#22-a-shared-test-library-implementing-the-helper-specs-must) |
| Under virtual-time advances, the idle timer disconnects an objects fixture | The fixture's idle interval is shorter than the advance | Set a large idle interval in the fake-clock fixture variant and document it in the notes | guide [2.2](../../../docs/writing-uts-spec-translator-skills.md#22-a-shared-test-library-implementing-the-helper-specs-must), "Document each fixture helper's scope" |
| Audit says clean but an assertion is missing | Counts summed with waits; commented assertions counted; helpers after the last test attributed to it | Fix the audit; keep shared helpers before the first test or in a separate file | guide [8.2](../../../docs/writing-uts-spec-translator-skills.md#82-audit-audit_translationpy-must) |
| Generated class clashes with a native test class | Name collision across targets | Collision detection or target-qualified filters | guide [8.1](../../../docs/writing-uts-spec-translator-skills.md#81-resolver-resolve_utspy-must) |
| Module translated with a guessed mapping | Notes file missing (silent `null`) or a placeholder | Resolver error for a missing notes file; refuse placeholder modules | guide [8.1](../../../docs/writing-uts-spec-translator-skills.md#81-resolver-resolve_utspy-must), [4](../../../docs/writing-uts-spec-translator-skills.md#phase-1-selection-steps-0-and-af) |
| Local build green, CI red | CI is stricter (warnings as errors, static analysis, type checking) | Compile as strictly as CI in the skill | guide [10](../../../docs/writing-uts-spec-translator-skills.md#10-verification-and-ci); `writing-derived-tests.md` "Build pipeline and CI checks" |
| A test fixed by hand reverts on the next run | The fix was made only in the generated file | Fix the skill, notes or UTS infra; regenerate | guide [5](../../../docs/writing-uts-spec-translator-skills.md#5-translation-rules) |
| Stale tests after a spec update | Renamed or merged IDs not followed | Re-sync mode; pair missing and orphan IDs; re-check assertions | guide [9.3](../../../docs/writing-uts-spec-translator-skills.md#93-renamed-merged-and-added-ids) |
| An upgraded skill lost hand-tuned rules, or existing UTS tests changed shape | The skill was regenerated or rewritten instead of upgraded in place | Upgrade in place, closing one chosen item at a time; keep the preserve list; compare with the baseline | [11.5](upgrade-existing-skill.md#115-step-u4-run-the-phases-scoped), [11.6](upgrade-existing-skill.md#116-step-u5-validate-without-regressions); guide [9.5](../../../docs/writing-uts-spec-translator-skills.md#95-upgrading-an-existing-skill-should) |
| The detector says `no` or `unclear`, yet the SDK has LiveObjects | The API is in another package or repo, a submodule, generated code, or uses names it doesn't know | Ask where the API lives; run it there (or with `--include-submodules`); read the files; the user decides at STOP-14 | [12.1](liveobjects-support.md#121-gather-the-evidence-step-1b-p-15) |
| A real Ably Pub/Sub SDK is rejected or asked about at STOP-16 | A fork-only clone (no `ably/…` remote), an SSH host alias not resolvable from the ssh config, the wrong path or a sparse checkout (`NO_SDK_FINGERPRINT`), a client the definition gate can't see (`NO_CLIENT_DEFINITION`: a wrapper gem, a new client name), or a repository not yet on the whitelist | Add an upstream remote for the `ably/…` repository, fix the ssh config, or point at the repository root. A repository not on the whitelist, or an SDK the gate can't see, needs `assets/eligibility.json` updated (add the name to `repositories`, with a `capabilityOverride` if needed) or the alias added to `assets/capability-names.json`: no override at run time | [13.2](orient.md#132-repository-eligibility-stop-16) |
| A skill this procedure built is classified S3 | Its records weren't kept, or are somewhere else, or it predates the provenance stamp | Rerun Orient with `--records <dir>`, or proceed with the full gap audit | [13.3](orient.md#133-state-classes), [13.7](orient.md#137-provenance-d-30) |
| A single skill is classified S4 | A dangling symlink, a `uts-to-*` directory without `SKILL.md`, or a skill whose language has no files in the repo | Name the skill with `--skill-dir` (Orient then classifies only that skill and lists the others under Problems), and route it as 13.5's S4 rows: diff-driven if its origin is `creator-records`, else the full gap audit. Or repair the install: approve each change (never delete without asking), then rerun Orient | [13.3](orient.md#133-state-classes), [13.5](orient.md#135-routing) |
| Orient offers to resume a run that finished | The Design record's Run status wasn't set to finished at Phase 7 | Restart, or set the Run status after checking the Final report | [13.6](orient.md#136-re-entry-resume-or-restart) |
| A REST-only SDK reported with realtime, or a full SDK reported REST-only | Realtime names only in comments, tests or docs; renamed clients the detector doesn't know; a client only reachable through a factory in an excluded directory or submodule | Read the evidence; correct the profile at STOP-17 with evidence; add a new client name to `aliases` in `assets/capability-names.json` (not the code) | [13.8](orient.md#138-capabilities-and-scope-stop-17-d-31) |
| Orient's Spec names line says FALLBACK, or a renamed spec type isn't found | The spec clone's IDL couldn't be parsed (a missing heading, a moved file, an old clone), so the detectors used the data file's minimal, possibly stale names | Fix or update the spec clone at STOP-1 and rerun; if the IDL's format changed, report the parser gap. Don't rely on the LiveObjects or capability verdicts until it says `spec` | [13.4](orient.md#134-the-state-summary-and-stop-13), [13.8](orient.md#138-capabilities-and-scope-stop-17-d-31) |
| The spec-clone sync says `FETCH_FAILED` although the machine is online | A sandbox denies writes under the clone's `.git` or network access; or a credential or SSH prompt was suppressed | Use the clone as it is for this run; the user allows the directory and network (Claude Code `/add-dir` or `permissions.additionalDirectories`; Codex a writable root and network), or fixes the remote's auth, then reruns | [13.9](orient.md#139-sync-the-spec-clone) |
| The sync says `NOT_SYNCED_NAMED_CLONE`, or Orient shows SPEC CLONE NOT SYNCED | The clone in use isn't the shared clone (a path the user named, or a skill installed from another clone): only the shared clone is synced | Expected. The user keeps that clone up to date; to have it synced, use the shared clone instead (no path, a path into it, or `ABLY_SPEC_CLONE` pointing at it) | [13.9](orient.md#139-sync-the-spec-clone) |
| The sync says `LOCKED` | Another run is syncing the same clone, or a crashed run left its lock | Use the clone as it is; if no other run is syncing, the user removes the reported lock file | [13.9](orient.md#139-sync-the-spec-clone) |
| The sync says `NOT_ON_MAIN`, and nobody meant to leave the shared clone on a branch | The clone was switched to test a spec change and left there | Use it as it is, or stop while the user switches it back; the sync never switches. To test branches, use a worktree of the shared clone instead | [13.9](orient.md#139-sync-the-spec-clone) |
| The spec clone's HEAD moved mid-run | This run's sync, or another run's fast-forward of the shared clone | Stop and ask whether to restart from the new SHA; never stamp the old SHA on files read after the move | [13.9](orient.md#139-sync-the-spec-clone), [2.6](../SKILL.md#26-pin-the-spec-clone) |
| Orient says the recorded spec SHA isn't in this clone | The records came from another clone, or from a branch whose commits were since deleted | In the shared clone, fetch the SHA after STOP-6 and rerun Orient; if it is still missing, run the full gap audit. In any other clone, never fetch: the user fetches it, or run the full gap audit | [13.9](orient.md#139-sync-the-spec-clone) |
| `SPEC_CLONE_INCOMPLETE` | The clone's checkout predates the guide or this skill (for example a `main` from before they were merged) | Follow the message: for the shared clone, sync it if `origin/main` has them; otherwise name a clone or worktree of a branch that has them | [13.9](orient.md#139-sync-the-spec-clone) |
| The side chosen at STOP-17 turns out wrong in Phase 1 (the test support or the internal-access route points elsewhere) | The side was chosen from Orient's evidence, before Phase 1 read P-13, P-14 and P-16 | Re-confirm it at STOP-3 with the Phase 1 evidence; a different side adds a decision-log entry that supersedes D-31 | [13.8](orient.md#138-capabilities-and-scope-stop-17-d-31), [4.9](phase-2-design-infra.md#49-step-2i-stop-3-approve-the-design-and-choose-the-scope) |
| A stop-point question is hard to find or answer: options with no visible question, internal IDs in the text, or STOP-17 asked before the run mode | It wasn't asked in the [asking.md](asking.md) format, or not in 13.1's order | One question per decision with one numbered option list, numbered in the order asked, in plain words; STOP-13 first, then STOP-17 only while it is open; one reply line | [asking.md](asking.md), [13.1](orient.md#131-run-it) |
| Sides reported for an SDK without doors, or a door's side wrong | A factory or door type whose name or path the data file doesn't know, or a door type under an unexpected path | Read the Side lines' evidence; correct the side at STOP-17; add the door type or path to `doorFactories.sides` in `assets/capability-names.json` | [13.8](orient.md#138-capabilities-and-scope-stop-17-d-31) |
| An infra defect reported as SDK-blocked | The objects smoke test fails, and it is blamed on the SDK without checking | SDK-blocked needs every self-test green and evidence naming an SDK not-implemented symbol; otherwise it is an infra stop | [12.5](liveobjects-support.md#125-an-sdk-blocked-objects-tier) |
| `objects` translated with no notes in a later run | No mapping entry, so the skill's step B offered `--create` | Give `objects` an entry even when out of scope: one module-level `unready` reason, no tier paths, never `unsupported` | [12.2](liveobjects-support.md#122-stop-14-recommend-then-ask) |
| Rules in the skill and the manual disagree | The skill inlined a copy of a semantic rule | Link to the source instead | guide ["What the skill owns"](../../../docs/writing-uts-spec-translator-skills.md#what-the-skill-owns-and-what-it-defers), [12](../../../docs/writing-uts-spec-translator-skills.md#12-lessons-learned) |
